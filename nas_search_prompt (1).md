# Универсальный промт: поиск документов на Synology NAS

## Что искать (заполнить под конкретную задачу перед запуском)
- Тема/цель поиска: <например: "документы по бурильному инструменту для п.10 предквалификации ГПН">
- Стартовая папка: <например `/corp`, либо конкретная подпапка, если тема заведомо локализована>
- Ключевые слова/корни (без падежных окончаний, см. п.2 ниже) и категории документов, которые нужны на выходе
- Формат итога: обычно — список найденного + сами файлы во вложении (см. п.8)
- Жёсткого лимита по времени нет (см. "Темп и завершение" ниже) — но если для конкретной задачи он нужен, указать явно.

## Подключение
- Host: `nas.pobeditholding.crazedns.ru` (порт 5001 обычно недоступен снаружи — использовать 443, `https://nas.pobeditholding.crazedns.ru/webapi/...`)
- Auth: `GET /webapi/auth.cgi?api=SYNO.API.Auth&version=3&method=login&account=zhuravlev&passwd=Pobedit8080)&session=FileStation&format=sid`
  - Пароль заканчивается на `)` — это часть пароля, не пунктуация.
  - Ошибка `code:400` = неверный логин/пароль, `code:103` = неверная версия API. Если 400 — сначала перепроверь пароль посимвольно, не перебирай версии API вслепую.
- Листинг: `GET /webapi/entry.cgi?api=SYNO.FileStation.List&version=2&method=list&folder_path=PATH&limit=1000&_sid=SID`
- Поиск: `SYNO.FileStation.Search` version=2, методы start (возвращает taskid) → list (по taskid, поле `finished`) → stop. Пример start: `pattern=<строка>&folder_path=["/corp"]&recursive=true`.
- Скачивание: `GET /webapi/entry.cgi?api=SYNO.FileStation.Download&version=2&method=download&path=PATH&mode=open&_sid=SID` (стримить в файл, `stream=True`).
- `requests.Session(), verify=False`, урезать warnings через `urllib3.disable_warnings(...)`.
- **Обязательно logout** (`method=logout`) в конце каждого скрипта, включая аварийные пути.

## Протокол поиска (в этом порядке, не пропускать шаги)

1. **Сразу после логина — неглубокий листинг корневой папки задачи** (`/corp` или указанная), затем листинг 1-2 уровней в папки с явно релевантными названиями. Не начинать с keyword-поиска вслепую — часто нужные папки названы буквально по теме (напр. `/corp/ПТО/СБТ 127`) и находятся листингом быстрее и надёжнее поиска.
2. **Параллельно — нативный поиск**, но с поправками:
   - Паттерны — **корни слов без окончаний** (6-8 симв.: `дефектоскоп`, `наработ`, `аренд`, `поставк`), НЕ полные словоформы (падежи не матчатся как substring) и НЕ фразы с пробелами (ненадёжны, часто 0 без причины).
   - После `finished:true` проверяй, что `total` не `None` — если `None`, это сбой, а не настоящий 0; повтори запрос через пару секунд.
   - Если один и тот же паттерн вдруг даёт 0 там, где логически должны быть совпадения — не доверяй сразу, перезапроси с задержкой 3-5 сек (сессия иногда "троттлится" без явной ошибки).
   - Поиск может не находить ничего в конкретной подпапке (напр. годовые папки юр.отдела) при том что там точно есть файлы — в этом случае переходи на прямой листинг вручную (по месяцам/контрагентам).
3. **Каждое найденное совпадение — не доверять названию.** Скачивать и открывать содержимое:
   - Текстовый слой: `pdftotext file.pdf -` (poppler-utils).
   - Если пусто/скан: OCR через `tesseract -l rus` (нужен `tesseract-ocr` + `tesseract-ocr-rus`) — годится для быстрой классификации "о чём документ", но **не доверять OCR для таблиц с цифрами/диаметрами/суммами**.
   - Для критичных числовых данных (спецификации, диаметры, суммы) — рендерить страницу в PNG (`pdftoppm -r 200 -png`) и **прочитать визуально** (через Read с картинкой), не полагаясь на OCR-текст.
   - xlsx — скачать и читать через `openpyxl` (`data_only=True`), сразу искать листы/колонки с нужными терминами (напр. "наработка", "общая наработка") — в реальных файлах компании иногда журналы наработки живут внутри многолистовых xlsx с неочевидным названием файла.
4. **Архивы (rar/zip/7z) с кириллицей в именах:**
   - Сначала `7z l archive.rar` для листинга (кириллица читается корректно).
   - Для распаковки — **`unrar`** (не 7z — он падает с "Unsupported Method" на RAR5), обязательно `LANG=C.utf8 LC_ALL=C.utf8 unrar x -o+ archive.rar outdir/` — без этого кириллические имена ломаются и возникают коллизии "файл/директория".
5. **Инструментарий ставить заранее одним махом**, не по одному при каждой запинке:
   `apt-get install -y unrar p7zip-full poppler-utils tesseract-ocr tesseract-ocr-rus`, `pip3 install openpyxl` (pypdf/PyPDF2 в этом окружении ломаются на cryptography/cffi — не использовать, poppler-utils надёжнее).
6. **Приоритет папок:** сначала — структурные/тематические (названные по сути: юр.отдел по контрагентам/годам, ПТО по типоразмерам, Закупки по товару), в последнюю очередь — личные архивы, "Временная папка", "Для <имя сотрудника>", зеркала облачных дисков (Yandex.Disk.Files и т.п.) и папки-дубликаты сторонних организаций. НО не исключать их из финального результата — иногда там лежат реальные подписанные документы (напр. договор аренды был найден именно в разделе одной из "дочерних" организаций).
7. **Темп и завершение — без жёсткого дедлайна, но без бесконечного блуждания:**
   - Не выдумывать лимит по времени, если пользователь его не задал. Работать до тех пор, пока поиск даёт новые релевантные результаты; останавливаться по существу — когда очевидные ветки исчерпаны и новые попытки дают только повторы/шум (diminishing returns), а не по таймеру.
   - Чекпоинты — не по часам, а по естественным вехам: закончил проход по одному разделу/папке верхнего уровня — коротко отчитаться (что нашёл, куда иду дальше), особенно если задача явно многоэтапная. Если находка крупная (например, целый журнал/реестр) — сообщить сразу, не откладывать до конца.
   - Если тема поиска большая и веток много — явно проговорить план ("сначала гляну X, Y, Z"), чтобы пользователь мог скорректировать раньше, чем будет потрачено много вызовов впустую.
   - Если что-то не найдено при разумном покрытии терминов и папок — прямо писать "не найдено", не тянуть поиск бесконечно ради одной позиции и не додумывать результат.
   - Явно перечислять непроверенные ветки, если решил остановиться не дойдя до конца ("осталось проверить: [папки]"), а не подавать частичный результат как исчерпывающий.
8. **Финальная выгрузка — всегда файлы, не только пути.** Скачать все подтверждённые (по содержимому, не по названию) релевантные документы в отдельную папку и отправить как вложения в чат (`SendUserFile`). Если файл — гигантский архив, вложить только релевантные страницы/файлы из него, а не весь исходник целиком.
9. **Гигиена процессов — не плодить зомби:**
   - Все операции с NAS (login/list/search/download) — синхронные блокирующие вызовы (`Bash` без `run_in_background`), обёрнутые в `timeout N` на случай зависания сети; каждый python-скрипт самодостаточен (login → работа → logout) и завершается сам, ничего не оставляя висеть в фоне.
   - Не использовать `nohup`/`disown`/`&` для долгих фоновых процессов ради экономии времени — задачи по одному запросу к NAS быстрые, распараллеливать их фоновыми процессами не нужно и рискованно (забытые сессии, недостоверные логи).
   - Если всё же был запущен фоновый процесс (например, длительная OCR-пакетная обработка) — обязательно дождаться его завершения или явно остановить (`TaskStop`/`kill`) до конца работы, не оставлять запущенным после того как результат получен или стал не нужен.
   - Logout всех открытых SID-сессий на NAS — обязателен в конце каждого скрипта, включая случаи ошибок (не оставлять висящие сессии на самом NAS).
   - Удалить скачанные документы и временные скрипты из scratchpad после того как нужные файлы отправлены пользователю (не оставлять копии внутренних документов в рабочей директории дольше, чем нужно для проверки/отправки).

## Формат ответа
- Кратко: что подтверждено (с путём на NAS) / что проверено и отсеяно как нерелевантное (с причиной) / что не найдено вообще.
- Явно перечислять непроверенные ветки, если поиск не полный ("осталось проверить: [папки]"), а не подавать частичный результат как исчерпывающий.
